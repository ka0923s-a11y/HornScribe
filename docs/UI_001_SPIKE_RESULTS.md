## 4. Toolchain findings (the real spike risk)

`stable-x86_64-pc-windows-gnu` **cannot build out of the box** on this machine —
three successive blockers were hit and resolved:

1. **`error calling dlltool 'dlltool.exe': program not found`** —
   rustc's GNU backend shells out to binutils `dlltool` to materialize
   `raw-dylib` import libraries used by `windows-link`/`windows-sys` (fails even
   for rlib crates such as `parking_lot_core`), and again when linking
   proc-macro DLLs (`serde_derive`, `tauri-macros`, …). Fix: install MinGW
   binutils. llvm-mingw's `bin/dlltool.exe` satisfies it.
2. **`lld: error: unable to find library -lgcc_eh` / `-lgcc`** — the
   `windows-gnu` target spec links GNU `libgcc`/`libgcc_eh`, which llvm-mingw
   (compiler-rt + libunwind based) does not ship. Workaround used: a shim dir
   (`C:/Users/ka092/mingw-shim`) containing `libgcc.a` ←
   `libclang_rt.builtins-x86_64.a` and `libgcc_eh.a` ← `libunwind.a`, passed via
   `RUSTFLAGS="-L <shim>"`. This is a *spike-local* hack, not a committed
   artifact. A real GNU toolchain (winlibs GCC) is the cleaner fix for
   CI/dev machines; pending decision recorded in §8.
3. **`ld.lld: error: too many exported symbols (got 89700, max 65535)`** —
   the Tauri template's `crate-type = ["staticlib","cdylib","rlib"]` makes GNU
   ld auto-export every symbol of the cdylib. Desktop-only needs `rlib`;
   `Cargo.toml` is changed accordingly (mobile embedding is a non-goal here).

With those resolved: `cargo build` (debug), `cargo build --release`,
`tauri dev` (vite + cargo run + window) and `tauri build` (NSIS installer)
**all succeed**. `tao`, `wry`, `webview2-com(-sys)` all compile and link for
`windows-gnu` — the feared WebView2/gnu failure did not materialize.

MSVC path: dead on this machine (no `cl.exe`/`link.exe`, no Windows SDK import
libs — VS BuildTools has MSBuild only). Unverified but expected to work on a
normal VS C++ install; CI should use msvc as the primary target.

`MainWindowTitle` (window present) → poll `msedgewebview2.exe` children tagged

`PrivateMemorySize64` for app + all WebView2 children.

## 6. Security baseline (MASTER_PLAN §4.8)

### `capabilities/default.json`

Explicit subset of `core:default` — app/event/path/resources/webview/window
defaults only; `core:menu`, `core:tray`, `core:image` deliberately excluded
(unused surfaces). **No plugin permissions at all**: no `fs`, `dialog`,
`shell`, `http`, `clipboard`, `asset` protocol — the frontend cannot touch the
filesystem. `tauri-build` compiled the file into the ACL manifest; unknown or
over-broad permissions would fail the build, so the file is self-checking.

### CSP (`tauri.conf.json → app.security.csp`)

```text
default-src 'self';
script-src 'self';
style-src 'self' 'unsafe-inline';
img-src 'self' data:;
font-src 'self';
connect-src 'self' ipc: http://ipc.localhost;
media-src 'self';
worker-src 'self';
object-src 'none'; base-uri 'self'; frame-ancestors 'none'; form-action 'none'
```

- `script-src 'self'`: bundled Vite modules only; **no `wasm-unsafe-eval` yet**
  (no WASM shipped). It will be added, scoped, when Verovio lands (Gate C).
- `style-src 'unsafe-inline'`: required — Fluent UI v9 (griffel) injects
  `<style>` rules at runtime. Styles can't load from anywhere else.
- `connect-src … ipc: http://ipc.localhost`: Tauri IPC channel.
- `img-src data:`: inline SVG/icon data URIs.
- `media-src 'self'`: future local playback cache will need either this or a
  narrowly-scoped asset scope — intentionally NOT enabled now.
- `assetProtocol.enable = false`: off until the playback-cache milestone needs
  it; then scope = explicitly opened files only (§4.8).

Caveat: the CSP guards the packaged webview (`tauri://`/`tauri.localhost`);
`vite dev` serves without it (HMR needs it) — config is still validated on
every `tauri build`.

## 8. Open questions / follow-ups

- **Choose the supported native toolchain**: MSVC (normal dev path) vs
  windows-gnu + real binutils. The llvm-mingw `libgcc` shim used here is a
  spike hack — replace with winlibs GCC or require MSVC CI images before
  anyone else builds.
- `freezePrototype: true` and removing `style-src 'unsafe-inline'` (griffel
  CSP nonce) are hardening candidates once we can runtime-verify them.
- Bundle identifier `dev.hornscribe` is provisional.
- Icon is a generated placeholder (staff + note); design pass deferred.
- Session-restore, F6 region cycling, `Space`/`J`/`K`/`L` transport keys and
  the real EMPTY→AUDIO_READY transition are next-spike scope.
