# 製品境界（PRODUCT_BOUNDARY）

> Status: 2026-09-24 起票（#190）。「やらないこと」「将来検討」を明文化し、
> 実装判断の基準とする。変更は issue 経由で合意してから更新する。

## 製品の核

HornScribe は**単一音源 → ホルン用移調楽譜**のデスクトップツール。
一般の JPOP・歌声・単旋律楽器の録音を、完全無料・オフラインで楽譜化し、
F管（+P5 記譜・-P5 移調メタデータ）と B♭管（+M2 記譜・-M2 移調
メタデータ、#156）の両記譜で演奏可能な譜面まで届ける。

## 3つの軸を分けて考える（#251）

「入力が1ファイルか」「出力がF管ホルン1楽器か」
「1人の奏者がそのまま演奏できるか」は別の軸であり、混同しない。

- **入力**: 常に単一音源（1ファイル / 1回の録音 — マイク録音・PC内再生
  （ループバック）の取り込みを含む）。ミックス音源も入力としては許可する。
  複数音源の投入は採譜キュー経由で逐次処理する（下のバッチ処理項）。
- **出力楽器**: ホルンのみ。記譜は F管（+P5）と B♭管（+M2、ダブルホルンの
  B♭側）の両プレゼンテーションを持つ（#156）。他楽器・総譜は対象外。
  例外として、ソース分離で得た伴奏ステムから採譜した**伴奏パート**
  （非移調の参照スタッフ）を任意で併記できる — これはホルン以外の楽器を
  出力対象に加えるのではなく、主旋律の文脈を失わないための解析成果物の
  添付であり、製品の主成果物の位置づけは変わらない。
- **演奏可能性**: 出力モードごとに定義が異なる（下表）。主成果物は
  「1人のF管奏者がそのまま演奏できる譜面」であり、それ以外の出力は
  その制約を明示した上で検出内容を失わないための保存形態とする。

### 出力モード

| モード | 内容 | 1人で演奏可能か |
|---|---|---|
| ソロF管パート | 単旋律。同時音を持たない。melody/mono/auto の主旋律結果 | **可能 — HornScribe の主成果物** |
| 複数F管パート（voices） | 検出した声部を複数のF管パートに分ける。複数奏者向けの重奏譜 | 1パートずつは可能。1人で全パートは不可 |
| 和音パート（chords） | 同時発音を1パート内の和音として保存する分析的表現 | **不可** — 原音の重音構造の記録であり、演奏譜ではない |
| 伴奏パート（accompaniment） | 伴奏ステムの採譜結果を非移調の別段として併記する参照出力 | **不可**（ホルン演奏譜ではない — 主旋律の文脈参照用の添付スタッフ） |

chords/voices は「検出した重なりを捨てない」ための機能であり、
「1人で演奏できる」という製品の約束の例外ではなく別用途の出力として扱う。
和音から1本の演奏可能な旋律へ reduce する機能は chord 記譜とは別問題として
設計し、`collapseToMelody`（「単旋律にまとめる」コマンド、#123）として実装済み。
同一オンセットの同時発音は最上声部を残し、オンセットの異なる重なりは
クリップして単旋律化する。chords/voices で検出した重なりを後から演奏譜に
畳み込む導線であり、解析出力の保持方針自体は変えない。

## やらないこと（現時点で非目標）

| 領域 | 方針 | 理由 |
|---|---|---|
| 歌詞 | 対象外 | 音声からの歌詞推定は別領域（ASR）。楽譜への歌詞記載も現状行わない |
| 反復記号 | 展開済み記譜のみ（反復フレーズの**検出**は #385 でレビューマーカーとして実装済み） | リピート・D.S./コーダへの畳み込みは構造解析＋記譜設計が必要。まず正確な通し記譜を優先 |
| 総譜・多楽器 | ホルンのみ（複数パートまでは可。記譜は F管/B♭管） | voices テクスチャの複数パートは「同じホルンの声部」として記譜する。他楽器は対象外 |
 | コードネーム | MusicXML `<harmony>` 出力 + アプリ内表示 + レビュー remedy + 検出済みシンボルの手動リラベルまで対応(#44/#335/#359) | #3 の和音マップを `<harmony>` として出力（確度の低い区間は出力しない）。アプリ内譜面にも描画され、`chord_uncertain` レビュー項目＋「次点に変更」(setChord) のワンクリック remedy を持つ。プロパティパネルのコード進行エディタで検出済みシンボルのラベルを直接訂正できるが、存在しない拍への新規追加・削除は行わない — あくまで解析結果の訂正であり、コード進行の採譜自体を主機能にはしない |
| バッチ処理 | 逐次キューは実装済み（複数投入・同時1ジョブ、#18）。それ以上の無人・並列バッチは非目標 | レビュー主導のワークフローが前提。キューは順に回すだけで、各結果は個別に要確認を通る |
| クラウド/有料API | 使用しない | 完全無料・オフライン運用が制約（demucs 等のローカルモデルは可） |

### 実装済みになった再評価候補

- ボーカル分離の前処理 — #187 で採譜オプションとして実装（center 抽出、
  `engine-vocal` extra では demucs による真の2ステム分離 #302）。
  配布版向けの組込み経路は分離アドオンとして
  `HornScribe-demucs-addon-*-win64.zip` をリリース資産公開済み（#165） —
  アプリ本体への同梱はサイズ上の理由で見送り、オプトイン配布を維持する。

## 将来検討（境界の外側だが再評価候補）

- 反復構造の畳み込み — 同一フレーズの繰り返し検出は実装済み（#385 stage 1、
  要確認リストの情報マーカー）。残件は検出結果をリピート記号・D.S./コーダへ
  畳む記譜側の設計
- 歌詞の手入力添付 — 推定ではなくユーザー入力なら境界内に収まる

## 精度に関する約束

- 推定が不確かな要素（拍子・調・スウィング・声部数）は推測で隠さず、
  ReviewIssue として提示する。ユーザーが確認・修正できることが
  「正しい楽譜」の一部である。
