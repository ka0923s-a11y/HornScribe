# FEAT-001: PC再生音源・マイク録音・楽譜自動演奏

> Status: Implemented (PR #61)
> Issue: #60(本体), #70-#77(レビュー指摘)
> Language: 日本語UIのみ
> Platform: Windows 11 first(WASAPI 依存)

---

## 1. スコープ

FEAT-001 は音源の入口を「ファイルを開く」以外に広げ、生成した楽譜を
その場で確認できるようにする。

- **PCの音を取り込む**: 再生デバイス出力を WASAPI ループバックで
  録音する。ブラウザで再生中の動画・ストリーミング・他アプリの音を
  そのまま採譜の入力にできる。取り込みメニューから対象デバイスを
  選べる(#73)。
- **マイクで録音**: キャプチャデバイス(マイク)から録音する。
  生演奏を吹き込んで採譜する用途。デバイス選択可(#73)。
- **楽譜の演奏(自動演奏モード)**: 生成済みスコアを WebAudio で発音し、
  追従カーソルと同期して鳴らす。

## 2. 設計上の決定

### 2.1 ループバックは Tauri コマンド(WASAPI)で実装

WebView2 は `getDisplayMedia` を提供しないため、ブラウザ API では
システム音源を取れない。`src-tauri/src/capture.rs` で WASAPI 共有モード
を直接叩く app-defined コマンドとして実装した。

コマンド群:

| コマンド | 役割 |
| --- | --- |
| `capture_start` | セッション開始(同時1本。busy 時は `CAPTURE_BUSY`)。`device_id`/`suggested_name` を受け取る |
| `capture_stop` | 停止して WAV を `appDataDir/recordings/` に保存し、パス+メタ情報(長さ/無音率/上限到達)を返す(#70) |
| `capture_cancel` | 録音を破棄 |
| `capture_status` | 進行中セッションの状態問い合わせ(経過時間 + 入力レベル) |
| `capture_devices` | 録音対象にできるエンドポイント一覧(#73) |
| `capture_pause` / `capture_resume` | 録音の一時停止/再開(#80)。停止中はクライアントを止めてパケットを捨てる(ギャップとして記録) |
| `recordings_info` / `open_recordings_dir` / `clear_recordings` | 録音フォルダの情報・開く・全削除(#78、設定画面用) |

ADR-0002 の自己制限コマンドと同じ考え方で、ACL に頼らず実装側に
制限を内蔵する:

- 取り込み対象は `capture_devices` が返す ACTIVE 状態の
  レンダー/キャプチャエンドポイントのみ(フリーのパス指定は不可)
- 連続録音は30分で自動停止(48kHz f32 stereo で ~1.3GB の手前)
- 出力は 16bit PCM WAV のみ
- WAV は `appDataDir/recordings/` に実ファイルとして保存し、フロントは
  `read_audio_bytes` で読む。プロジェクトの `sourceAudio`
  (originalPath/contentHash)に載るのでリリンク可能(#70)

### 2.2 ブラウザ dev フォールバック

`src/capture/runtimePorts.ts` で実行環境を分岐する。ブラウザ dev では
マイクのみ `getUserMedia` + `MediaRecorder` で録音でき、ループバックは
明示的に `UNSUPPORTED` を返す(コピー: 「PCの音の取り込みは
デスクトップアプリでのみ利用できます」)。レベルメーターは
AnalyserNode で供給する。

### 2.3 録音物は `RecordedAudioRef` としてインポート経路に合流

録音完了後は `ImportController.importRecording` で `LoadedAudio` 化し、
ファイル選択と同じ AUDIO_READY 状態に着地する。Tauri では録音は
`appDataDir/recordings/` の実ファイルとして残り、`path` +
`contentHash` がプロジェクトに保存される(#70)。ブラウザ dev では
メモリ上の Blob のみ(永続化なし)。

### 2.4 録音開始前の置き換え確認(#76)

録音完了 = 現在の音源(と楽譜)の置き換えという単一ドキュメント前提の
ため、音源またはスコアが既にある状態で録音を始める場合は alert
ダイアログで確認する。また、録音開始時に楽譜の演奏が鳴っていると
ループバック/マイクに混入するため、開始と同時に audition を自動で切る
(録音中は audition コマンド自体も無効)。

### 2.5 楽譜演奏は実音(コンサートピッチ)

`ScorePlaybackSynth` は `PlaybackTable`(Verovio timemap)とコンサート
表示の `ParsedNote` マップを結合して発音する。F管表示中でも実音で鳴る
(採譜結果の確認用途に合わせる)。音色は三角波+サインの簡易合成で、
外部音源・サウンドフォントには依存しない。

スケジューリング方式:

- `ScoreCursorClock` の subscribe(~10Hz + 遷移時)に追従
- 400ms 先読み + `scheduledUntilMs` ウォーターマークで重複発音を防止
- ループ範囲・再生レート・シーク(>400ms のジャンプ検出)に追従
- AudioContext は遅延生成(トグルを有効にした時点で作成)

### 2.6 元音源との同時再生(#72)

楽譜演奏は元音源の再生と独立している。両方が鳴る状態は「採譜結果と
原音の聴き比べ」として許容しつつ、トランスポートのスピーカーボタンで
元音源だけをミュートできる(楽譜の演奏だけを聴く用途)。ミュートは
メディア要素の属性なので、ループバック録音中に切っても録音対象の
音は止まらない。

## 3. UI 上の振る舞い

- EMPTY 状態: 「このPCの音を取り込む」セクションに2ボタン
  (PCで再生中の音を録音 / マイクで録音)を追加
- コマンドバー: マイクアイコンの取り込みメニュー(2項目 + デバイス
  選択セクション#73)。録音中は
  「録音を終了して取り込む」「録音をやめる」に置き換わり、経過時間を表示
- 波形領域: 録音中はパルスドット + 経過時間 + デバイス名 +
  入力レベルメーター(#71)を表示
- トランスポート: 「楽譜を演奏」トグル(スコアがある時のみ有効、
  ショートカット P #75)+ 元音源ミュート(#72)
- 録音中は採譜・楽譜演奏コマンドを無効化
- ほぼ無音(無音率95%以上)の録音は取り込み後にアナウンスする
- 30分の連続録音上限に達すると自動停止し、その旨をアナウンス(#74)
- 音源/楽譜がある状態での録音開始は置き換え確認ダイアログを挟む(#76)
- 録音中は一時停止/再開ボタンを使える(#80)。一時停止中は経過時間が
  止まり、停止中の音は録音に混入しない(ギャップとして記録)
- 録音中にアプリを閉じようとすると確認ダイアログを出す(#81)
- マイクのアクセス拒否・録音中のデバイス切断は専用の案内文で通知
  する(#79 — ステータスポーリングで停止を待たずに検出)
- 設定 → 録音 で保存先の場所・件数・使用量を確認し、フォルダを
  開く/全削除できる(#78)。録音ファイルはプロジェクトの
  `sourceAudio` に載るため同梱はせず、明示的な削除のみ行う

## 4. コピー

新規キーは `protocol/copy/ja-JP.json` の `menus.file`/`transport`/
`capture` と `src/strings/ja.ts` に追加。録音中ラベルはソースで分岐する:

- ループバック: 「取り込み中」
- マイク: 「録音中」

## 5. 制限と今後の候補

- ループバックは Windows/WASAPI 限定。macOS/Linux は未対応
- 録音物は `appDataDir/recordings/` に残る — 設定 → 録音 で管理できる
  (#78)。自動削除ポリシー(日数/容量)は別途検討
- 楽譜演奏はピッチ確認用の簡易音色。強弱・歌口は未考慮
- 録音開始/停止にキーボードショートカットは未割当(停止は Ctrl+Enter)
