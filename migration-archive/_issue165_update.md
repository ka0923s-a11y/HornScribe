## 進捗記録（lead-track ゲート + rescue パス、#169 派生修正）

### 今回マージした変更（#170, #171）

1. **lead-track 同意ゲート**（#171）: 分離後推定を pYIN に無条件解決していた #316 の設計が、bleed-heavy な stem で壊滅的であることを実測（very-quiet-lead で pYIN 0/38 vs BP 仲裁 35/38）。分離推定は単音とは限らない — ベース/パッドが残ると pYIN がそのラインを追従する。auto + vocalIsolation 時に BP-rescue と pYIN を並走させ、`clean_monophonic` 後の BP ラインとの**同セミトーン・時間重み**同意度 >= 0.6 でのみ pYIN を採用。同意度はオクターブを加点しない（伴奏ベースは主旋律とピッチクラスを共有するため）。
   - 実測: very-quiet-lead 同意度 0.0 → BP 採用、jpop-mix-hard-vocal 0.188 → BP 採用。
2. **rescue パス**（#171）: 製品閾値（onset 0.4 / frame 0.3）に加え、感度閾値（0.25 / 0.18）の第2パスを分離推定に実行。**base イベントと >30ms 重複する候補はどのピッチでも拒否**する厳密加法ルール — 誤仲裁の第2推測を防ぎ、検出ホールのみを埋める。一律低閾値化は jpop-mix-vocal で回帰することを実測済みのため、空きスパン限定で採用（4フィクスチャ全て 1.0 維持）。
3. **demucs 無音 stem ガード**（#170, #169 として分離）: demucs が非ボーカル入力に残渣のみの stem を返す致命的回帰（0.8947 → 0.3421）を検出・修正。

### ベンチ結果（全29件）

- **28件 pitchAcc 1.0**（vocalIsolation 系 jpop-mix-vocal / jpop-mix-hard-vocal / quiet-lead-mix を含む）
- very-quiet-lead: **0.8947**（3 miss / 3 extra / 1 octave、変わらず）

### 残存限界の正直な評価

very-quiet-lead の残り3音は「検出なし」ではなく、**誤ピッチ検出がクリーニング段階で誤仲裁**されるケース — raw には正しいピッチが遅発音・断片で存在する。以下を測定の上いずれも棄却済み:

- BP 一律低閾値（0.25/0.18 以下）: 他フィクスチャで誤検出増の回帰
- HPSS 前処理 / repet+center / mask 変種: 改善なし
- ハイパス（180–300Hz）: fundamental 消失でオクターブ誤り増
- スペクトル再検証: 伴奏帯域が攪乱

**結論**: −9.5dB SNR では「どちらのピッチが正か」自体が音声上曖昧で、無料スタックの単独推定ではこれ以上の改善は仲裁の信頼度ではなく**分離品質**に依存する。本物のボーカル素材では demucs 経路（#169 で健全化済み）が最有力。合成フィクスチャの "vox" 音色では demucs が非声判定するため評価不能 — 実素材での追加検証が次の一手。
