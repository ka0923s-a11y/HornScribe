## Summary

* New `export.openInMuseScore` command (§13 高度編集): overflow menu → 「MuseScoreで開く」 hands the **live** score — current pitch view (コンサート/F管) and user edits included — to the MuseScore GUI.
* New Rust command `open_in_musescore`: stages the MusicXML to a temp file (millisecond-unique name so re-opens after edits never overwrite a file the GUI holds) and spawns the detected/user-pinned executable without blocking.
* Path resolution reuses the export probe: `detect_tools` result + 設定 → ツール override. Missing MuseScore announces the recovery path (設定 → ツールで場所を指定) via the status bar instead of a dead menu item.
* `ExportPort.openInMuseScore` is optional; the mock honours the `hornscribe.dev.museScore=missing` dev flag so the recovery announce is reviewable in `vite dev`.
* Fixed a stale-closure bug in the command context: `pitch`/`toolOverrides`/`exportPort` were missing from the `ctx` useMemo deps.

Closes #117.
