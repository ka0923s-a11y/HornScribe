## 背景\n\n録音開始の失敗は CaptureIssue で分類され EMPTY 状態ではインライン表示されるようになったが、以下の経路が弱い:\n\n- **マイク権限の拒否**(OS のプライバシー設定やブラウザの権限プロンプトで拒否)が汎用の「録音に失敗しました」に落ち、OS 設定への誘導が無い\n- **録音中のデバイス切断**(USBマイクの抜去等)はキャプチャスレッドのエラーとして stop 時にしか表面化しない — 録音中に即座に気づけない\n- ループバックで「既定の再生デバイス」が変更された場合、録音は旧デバイスを追いかけ続ける(仕様コメント未整備)\n\n## 提案\n\n- 権限系エラー(ERROR_ACCESS_DENIED / NotAllowedError)を専用 issue kind に分類し、「設定 → プライバシー → マイク」への誘導コピーを出す\n- 録音中のデバイス消失を status ポーリングで検出して即エラー表示\n- 既定デバイス変更時の追従/固定のポリシーを明文化\n\n## 関連\n\n- #60 FEAT-001, #73(デバイス選択), PR #61
