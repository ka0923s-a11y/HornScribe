## 症状（実機検証で観測）
波形ストリップ上のツールチップ付きボタン（#402 ノートオーバーレイ切替、選択アクション等）で、ツールチップが開いている間に同じ場所を素早く再クリックすると**クリックがボタンに届かない**。puppeteer の CDP クリックで再現: 1回目はトグルでき、2回目は無反応。

## 原因（調査済み・修正ブランチあり）
Fluent v9 のツールチップはポータルノード（`data-portal-node="true"` の div）内に描画される。このノードが `fui-FluentProvider` + `hs-provider` クラスを持ち、アプリの `.hs-provider { height: 100% }` ルールを拾う。絶対配置のツールチップ内容物は親のサイズを持たせないため、本来 0 高さのはずのラッパーが **全ビューポートの透明オーバーレイ**となり、ツールチップ表示中はその位置のクリックを全て横取りする。

## 修正内容（codex/note-overlay ブランチで実装済み）
`.hs-provider` → `#root > .hs-provider` にスコープ。アプリルート直下のプロバイダのみ高さを持ち、ポータルノードは 0 高さに畳まれてヒットテストから外れる。

## 検証
- off-state で `elementFromPoint` がボタン内アイコンを返すことを実機確認（修正前はポータルラッパーが最前面）
- 影響はツールチップ以外のポータル（Dialog/Menu/Popover）にも及びうるため併せて監査

## 影響
ツールチップ付き小ボタンの連続操作（オーバーレイ切替、選択ツールバー等）が実ユーザーにも取りこぼされうるユーザビリティ不具合。
