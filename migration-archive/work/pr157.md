## Summary

Fixes #157. tempo_map BPM is defined in primary-beat units (musician BPM
— 6/8 counts dotted quarters), but two consumers read it differently:

- notation/to_music21.py emitted MetronomeMark(number=bpm) with the
  default quarter referent, so a 6/8 score at dotted-quarter=60 was
  written as quarter=60 — Verovio (and any MusicXML importer) played it
  1.5x too slow.
- export/midi.py derived set_tempo as bpm * 4/beat_unit (payload-beat
  semantics), so the same score played 3x too slow — and disagreed with
  the MusicXML by another factor of 2.

Simple meters (4/4, 3/4 — the common J-pop case) were unaffected
because primary beat == payload beat == quarter.

## Changes

- to_music21.py: MetronomeMark gets referent=duration.Duration(
  primary_beat_ql) using the existing primary_beat_beats() helper, so
  6/8 exports beat-unit=quarter+dot and sound tempo in quarters/minute
  (what Verovio's timemap reads).
- midi.py: set_tempo now derives from primary_beat_beats, matching the
  notation rate.
- Regenerated the meter_68_eighths goldens (the only affected fixtures)
  and corrected test_eighth_beat_unit_tempo, which enshrined the buggy
  payload-beat semantics.

## Tests

- New: test_compound_meter_tempo_mark_uses_dotted_quarter asserts the
  6/8 export shows dotted-quarter=60 and tempo=90.
- pytest tests/python: 620 passed; ruff + mypy clean.
