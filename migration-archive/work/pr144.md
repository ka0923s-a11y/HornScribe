## Summary

Closes #132 — option 3 (the product-boundary fix): recordings a project references now live outside the retention sweep entirely.

- **Rust copy_recording_to_managed**: copies recordings/<name>.wav into appDataDir/sources/, the managed area retention never touches. Same bare-name validation as delete_recording; same-name reuse when bytes match (re-saving the same take does not duplicate), -N suffix on real collisions; allowed while recording since it only reads finished WAVs.
- **saveProjectFlow**: when the current audio is a recording inside the recordings dir, it is copied to sources/ first and the saved sourceAudio.originalPath points at the managed copy. contentHash still verifies (same bytes). Non-recording sources and copy failures keep the original path — keepNames protection (#137) remains the safety net.
- **recordingNameUnder**: shared dir-prefix check (case/slash-insensitive, sibling dirs rejected), unit-tested.

Result: 録音=一時作業領域 / プロジェクト=永続成果物 — a saved project can no longer lose its source to the retention policy, even for projects outside the recent-projects MRU.
