## Summary

Surfaces an honest warning when the monophonic pYIN backend runs under a texture that may carry polyphony. Closes #181.

pYIN tracks exactly one line by construction. With texture=voices the user explicitly asked for multi-part output; with texture=auto the source may be a mix. In both cases the result silently contains only the dominant line — now the review list carries a whole-piece issue explaining that.

## Changes

- New ReviewReason.monophonic_backend emitted when backend=pyin and texture is voices (severity warning — explicit request violated) or auto (caution — mix possible). texture=mono/melody stays quiet: those pairings are intentional.
- Evidence carries backend + texture so the UI can present the facts.
- Desktop: reason added to the engine-reason mirror, copy-key list, and score union type; Japanese copy added to both ja.ts and the canonical ja-JP.json deck (pYIN whitelisted as a proper noun in the copy-deck test).

## Verification

- New pipeline tests: voices+pyin warns, auto+pyin warns, mono+pyin stays quiet, basicPitch+voices stays quiet.
- pytest (review/transcription/copy-deck), ruff, mypy, tsc, vitest all green.
