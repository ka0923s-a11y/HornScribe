#2 UI-002: Python sidecar IPC and lifecycle spike

## Goal

Prove that the Tauri shell can reliably supervise a Python HornScribe engine process.

## Depends on

- UI-001
- FND-002 provides the runtime choice before ADR acceptance; this spike may begin with a tiny mock Python worker.

## Initial protocol

Newline-delimited JSON over stdin/stdout:

- protocol stdout only
- diagnostics on stderr
- request IDs
- protocol version
- structured progress
- structured errors
- cancellation request

## Spike methods

- `system.handshake`
- `system.ping`
- `jobs.demoLongTask`
- `jobs.cancel`
- `system.shutdown`

## Acceptance criteria — protocol/lifecycle

- [ ] worker launches in dev and packaged app
- [ ] handshake reports protocol/backend version/capabilities
- [ ] request/response correlation works
- [ ] progress streams without blocking UI
- [ ] timeout is handled
- [ ] malformed message is contained safely
- [ ] stdout remains protocol-clean
- [ ] stderr logs are captured separately
- [ ] worker crash does not terminate UI
- [ ] worker restart works without restarting UI
- [ ] incompatible major protocol version fails clearly
- [ ] automated parser/lifecycle tests exist

## Acceptance criteria — real backend gate

Before ADR-0002 can become Accepted:

- [ ] selected FND-002 runtime can be packaged as the real sidecar
- [ ] one real Basic Pitch smoke job runs offline
- [ ] cancellation behavior during real inference is measured
- [ ] if cooperative cancel is not prompt, worker terminate/restart fallback is demonstrated
- [ ] existing project state survives worker failure/restart

## Non-goals

- binary audio through JSON
- gRPC/local HTTP
- complex process pool before evidence requires it
