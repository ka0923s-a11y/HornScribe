#24 UI-012: Command registry, keyboard model, and focus architecture

## Goal

Make keyboard behavior a first-class application architecture rather than scattered component key handlers.

## Depends on

- UI-010
- UI-011

## Deliverables

Create a centralized command registry covering:

- Open
- Transcribe
- Play/Pause
- Stop
- Jump back/forward
- Loop
- Concert view
- F-Horn view
- Review next/previous
- Undo/Redo
- Export
- Score zoom
- Focus major regions

## Initial shortcuts

- Ctrl+O
- Space
- Shift+Space
- J/K/L
- Ctrl+L
- Ctrl+1 / Ctrl+2
- Ctrl+Z / Ctrl+Shift+Z
- Ctrl+E
- Ctrl++ / Ctrl+- / Ctrl+0
- F6 candidate for major-region navigation

## Focus requirements

- dialog close restores opener focus
- temporary popovers do not lose logical focus
- focus-visible is always obvious
- text editing suppresses transport shortcuts where appropriate
- disabled commands remain non-executable via shortcut

## Acceptance criteria

- [ ] no primary command uses ad-hoc component-local keyboard logic
- [ ] all commands have Japanese labels
- [ ] keyboard-only core path exists
- [ ] shortcut conflict test exists
- [ ] focus restoration tests exist
- [ ] Narrator announces command labels/states correctly in smoke test
