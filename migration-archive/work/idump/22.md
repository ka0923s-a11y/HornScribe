#22 UI-010: Design tokens, themes, and component state gallery

## Goal

Create HornScribe's production design-system foundation before feature screens accumulate one-off styling.

## Depends on

- UI-001
- UI-006

## Source of truth

- docs/DESIGN_SYSTEM.md
- docs/JAPANESE_UI_COPY.md

## Deliverables

- semantic color tokens
- typography tokens
- spacing tokens
- radius/elevation tokens
- motion tokens
- light/dark/system themes
- reusable component primitives
- internal component gallery/dev route

Required primitives:

- Button
- IconButton
- SegmentedControl
- Tooltip
- Popover
- Menu
- Slider
- NumericField
- Select
- Progress
- Status/Review badge
- Panel
- Dialog/Sheet

## State matrix

Every interactive primitive must demonstrate:

- default
- hover
- pressed
- focus-visible
- selected where applicable
- disabled
- loading
- error where applicable

## Acceptance criteria

- [ ] no feature component depends on raw hard-coded colors
- [ ] Japanese labels are the canonical examples
- [ ] light/dark/system work
- [ ] standard text contrast passes >=4.5:1
- [ ] non-text interactive boundaries pass >=3:1
- [ ] focus indicator is obvious in light/dark
- [ ] reduced-motion behavior exists
- [ ] icon-only buttons have Japanese tooltip + accessible name
- [ ] component gallery includes visual regression fixtures
- [ ] 1366x768 / 150% scaling smoke passes

## Non-goals

- waveform
- score renderer
- final app shell
