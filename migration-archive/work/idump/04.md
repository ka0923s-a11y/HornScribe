#4 UI-004: Waveform, loop, zoom, and playback spike

## Goal

Validate waveform, transport, local-media security, looping, and timing behavior for transcription review.

## Depends on

UI-001.

## Hypothesis

Use wavesurfer.js 7.x behind a HornScribe `TransportController`/waveform adapter.

wavesurfer is not allowed to become the application source of truth.

## Local file flow

Prefer:

```text
source audio (backend-owned)
→ normalized playback cache
→ narrowly scoped Tauri asset protocol
→ waveform/transport
```

Do not grant the WebView broad filesystem access.

## Fixtures

- ~30 sec synthetic audio
- ~3 min audio
- ~10 min audio

No copyrighted commercial audio in repo.

## Required capabilities

- render
- seek
- hover time
- pan/zoom
- region select and adjustable handles
- loop
- optional minimap experiment
- 0.5x / 0.75x / 1x / 1.25x / 1.5x
- pitch preservation where supported

## Measurements to record

- initial waveform load/render time
- seek latency
- visual playhead jitter
- repeated-loop drift
- memory at 30 sec / 3 min / 10 min
- pan/zoom responsiveness
- playback-rate/preserve-pitch behavior
- cache format/size

## Acceptance criteria

- [ ] local playback cache works offline
- [ ] Tauri asset scope is narrow and documented
- [ ] TransportController abstraction exists
- [ ] seek/selection/loop work
- [ ] measurements above are recorded, not replaced with “feels smooth”
- [ ] playhead updates do not rerender the full React app at frame rate
- [ ] source file is never modified
- [ ] no runtime network dependency
- [ ] selected cache strategy is documented or blocker recorded

## Non-goals

- spectrogram
- raw transcription note overlay
- final transport styling
