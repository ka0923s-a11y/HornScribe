#31 UI-009: Preproduction Japanese interaction prototype pack

## Goal

Validate HornScribe's information hierarchy and interaction model before production feature components are built.

## Depends on

- UI-001
- UI-006

Real backend integration is not required; deterministic mocked state is preferred.

## Prototype states

### P1 — App shell

- command bar
- waveform placeholder
- score placeholder
- properties
- transport

### P2 — Japanese density

Render:

- 1366x768
- 150% Windows scaling
- long Japanese labels
- long Japanese error
- light/dark

### P3 — Score interaction

Mock:

- note selection
- properties update
- playback highlight
- Concert/F-Horn switch
- follow suspend/resume

### P4 — Review

Mock 5 ReviewIssues:

- previous/next
- source replay
- resolve
- pitch correction
- undo

Must be operable keyboard-only.

### P5 — Export/error recovery

Mock:

- normal export
- MuseScore missing
- permission error
- worker crash

## Acceptance criteria

- [ ] score is visually dominant
- [ ] primary action is obvious in each state
- [ ] no English placeholder copy is visible
- [ ] 1366x768 remains usable
- [ ] 150% scaling has no clipped primary controls
- [ ] properties can collapse without losing task completion
- [ ] review flow can be completed keyboard-only
- [ ] error surfaces always have a recovery action
- [ ] screenshots are attached/recorded for all prototype states
- [ ] findings that alter interaction architecture update docs/GUI_UX_SPEC.md before production implementation

## Non-goals

- final visual polish
- real Basic Pitch
- real MusicXML export
- production persistence
