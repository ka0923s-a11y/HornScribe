#23 UI-011: Responsive application shell and information architecture

## Goal

Implement the permanent HornScribe workspace structure so feature teams do not invent different layouts.

## Depends on

- UI-010
- UI-003/UI-004 may remain placeholders at first

## Source of truth

docs/GUI_UX_SPEC.md

## Layout

- title bar
- command bar
- waveform region
- score workspace
- contextual properties
- transport
- job/status surface

## Required breakpoints

- >=1600 px
- 1200–1599 px
- 1100–1199 px
- minimum width around 1100 px

## Behavior

- score remains primary
- properties collapses/drawers before score becomes unusably narrow
- secondary commands move to overflow
- no app-level horizontal scrolling
- panel resize/clamp behavior deterministic

## Acceptance criteria

- [ ] 1366x768 works
- [ ] 1920x1080 works
- [ ] 150% and 200% scaling smoke passes
- [ ] properties can be closed
- [ ] toolbar never scrolls horizontally
- [ ] Japanese command labels do not clip
- [ ] keyboard focus moves logically among major regions
- [ ] layout state can be restored after restart
- [ ] score receives the majority of workspace area in normal state

## Non-goals

- final waveform/score implementation
- feature-specific inspectors
