#21 QNT-007: Quantizer benchmark, ablation study, and weights v1 freeze

## Goal

Demonstrate that HSQ-v1 improves readable rhythm transcription over simpler baselines, then freeze a reproducible weights/profile version.

## Depends on

- QNT-006

## Baselines

- B0 nearest 16th
- B1 nearest binary/triplet grid
- B2 music21 Stream.quantize
- B3 HSQ timing-only ablation
- B4 full HSQ-v1

## Test layers

### Synthetic

- straight rhythms
- jitter ±20/50/80 ms
- global latency
- rests
- articulation gaps
- 4/4, 3/4, 2/4, 6/8
- triplets
- syncopation
- barline crossing
- horn-like repeated notes / sustained notes / breath gaps

### Local private horn benchmark

Under gitignored `benchmarks/local/`.

Do not commit copyrighted material.

## Metrics

Record:

- exact onset accuracy
- onset error in ql
- exact note-value accuracy
- duration error
- rest correctness
- triplet classification
- symbol_count
- tie_count
- rest_count
- tiny_rest_count
- tuplet_group_count
- strong_boundary_obscured_count
- runtime
- user correction count/time where available

Optional score-level:

- MUSTER onset/offset error

## Ablations

At minimum compare:

- no IOI term
- no notation complexity
- no tiny-rest penalty
- no mode-switch penalty

## Acceptance criteria

- [ ] benchmark command is reproducible
- [ ] every run records HornScribe commit, HSQ version, weight version and fixture hash
- [ ] full HSQ beats nearest-grid baselines on intended readability fixtures
- [ ] notation complexity term demonstrates measurable benefit on at least one non-trivial fixture class without unacceptable timing regression
- [ ] tiny-rest handling improves horn-like articulation fixtures
- [ ] triplet false positives are measured
- [ ] typical 3–5 min monophonic quantization runtime is recorded
- [ ] selected `weightsVersion=1` is documented
- [ ] chosen defaults are updated in docs/QUANTIZER_DESIGN.md
- [ ] known failure classes are documented

## Decision gate

Do not call HSQ-v1 production-ready until this issue passes.
