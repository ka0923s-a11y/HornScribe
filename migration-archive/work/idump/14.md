#14 UI-006: Japanese-only UI language and copy foundation

## Goal

Make Japanese the only user-facing language in HornScribe and prevent English placeholder copy from becoming production UI.

## Product rule

The application UI is Japanese-only.

Do not implement:

- English UI
- locale switcher
- en-US product copy

Technical proper nouns such as MusicXML, MIDI, FFmpeg, MuseScore, Basic Pitch and file paths may remain in their standard form, but surrounding explanatory copy must be Japanese.

## Deliverables

- use `docs/JAPANESE_UI_COPY.md` as the copy standard
- common status/error/review wording definitions
- Japanese accessible names for component primitives
- Japanese sample states in component/dev preview
- Japanese empty/loading/error fixtures

A full translation framework is not required.

## Acceptance criteria

- [ ] all user-visible app-shell labels are Japanese
- [ ] menu/button/dialog/tooltip text is Japanese
- [ ] accessible names are Japanese
- [ ] no language selector exists
- [ ] no English fallback copy is visible in normal operation
- [ ] proper nouns are wrapped in Japanese explanatory text
- [ ] standard terminology follows `docs/JAPANESE_UI_COPY.md`
- [ ] Japanese text is tested at Windows 100%, 150%, and 200% scaling
- [ ] Yu Gothic UI / Meiryo fallback is verified
- [ ] IME composition works in editable text fields
- [ ] golden screenshots use Japanese as the canonical UI
- [ ] error states for FFmpeg/MuseScore/worker failure are Japanese

## Non-goals

- multilingual/i18n system
- English localization
- translating raw developer logs or stack traces that are not part of normal UI
