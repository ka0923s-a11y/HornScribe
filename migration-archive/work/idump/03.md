#3 UI-003: Verovio interactive score rendering spike

## Goal

Validate Verovio WASM as HornScribe's interactive score renderer and prove stable canonical-note mapping.

## Depends on

FND-001 defines canonical identity. ENG-001 provides authoritative Concert/Horn fixtures; an interim static fixture may be used to start the renderer spike.

## Fixtures

At minimum:

1. concert melody
2. same music as Horn in F written pitch
3. ties across barline
4. accidentals/key signature
5. multiple systems/pages

Each note fixture must have deterministic MusicXML `note/@id`.

## Required interactions

- MusicXML → SVG
- canonical note ID → MusicXML ID → rendered element
- click rendered note → canonical note ID
- highlight selected/active note without full score rerender
- time → score element where supported
- score element → time where supported
- zoom/resize
- Concert/Horn switch while preserving canonical musical location

## Acceptance criteria

- [ ] runs fully offline; no CDN
- [ ] representative MusicXML renders correctly
- [ ] Horn written pitch renders correctly
- [ ] stable canonical mapping survives renderer reload
- [ ] note selection/highlight uses DOM/CSS update rather than full rerender
- [ ] active-note update path is measured/profiled
- [ ] 100/150/200% DPI smoke tests pass
- [ ] renderer failure is recoverable
- [ ] license/attribution is documented
- [ ] accessibility strategy does not depend on raw SVG alone

## Decision gate

If stable identity, interaction, or accessibility has a blocker, run a bounded OpenSheetMusicDisplay comparison before changing the architecture.
