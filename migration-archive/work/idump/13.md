#13 ENG-001: Deterministic concert/Horn core, MusicXML identity, and export semantics

## Goal

Implement the exact music-domain behavior that must be correct before ML or polished UI is trusted.

## Depends on

FND-001.

## Scope

- canonical concert-pitch score representation
- Horn in F written-pitch projection
- key signature transposition
- stable MusicXML note IDs
- Horn MusicXML transpose metadata
- MusicXML round-trip tests
- explicit playback MIDI semantics

## Required invariants

```text
Concert C4 -> Horn written G4
Concert F#4 -> Horn written C#5
Concert Bb3 -> Horn written F4

Concert C major -> Horn G major
Concert F major -> Horn C major
Concert Bb major -> Horn F major
```

Horn MusicXML:

```xml
<transpose>
  <diatonic>-4</diatonic>
  <chromatic>-7</chromatic>
</transpose>
```

because MusicXML transpose describes written -> sounding.

## MIDI contract

MVP default MIDI is:

`playback.mid` = sounding/concert pitch.

Do not create an ambiguous default `horn_in_f.mid` whose written notes sound a perfect fifth too high in generic MIDI players.
