#5 UI-005: Unified score ↔ audio synchronization spike

## Goal

Validate HornScribe's core UX: precise two-way synchronization among audio time, waveform, canonical score identity, and rendered notation.

## Depends on

- FND-001
- UI-003
- UI-004

## Required model

One authoritative transport clock.

Synchronization is by time/canonical IDs, never by matching scroll positions.

Canonical chain:

```text
audio seconds
↔ beat/tempo mapping
↔ canonical note IDs
↔ MusicXML IDs
↔ rendered score elements
```

## Required interactions

### Playback

- clock → waveform playhead
- clock → active score note/measure
- optional score follow

### Score click

- rendered note → canonical note ID → audio onset → seek

### Waveform click

- waveform time → score context / nearest meaningful canonical element

### Loop

- waveform time range → loop state
- corresponding score passage indicated

### Follow playback

- follow on
- manual score navigation suspends follow
- explicit Resume Follow

## Acceptance criteria

- [ ] authoritative transport implementation is documented
- [ ] waveform click seeks score context
- [ ] score note click seeks audio
- [ ] active score highlight follows playback
- [ ] loop is represented in both time and score context
- [ ] manual scrolling does not fight follow
- [ ] Resume Follow is explicit
- [ ] Concert/Horn switch preserves canonical selection and transport time
- [ ] playback continues correctly through view switch
- [ ] synchronization error is measured on deterministic fixtures
- [ ] loop drift is measured
- [ ] timing/mapping logic has UI-independent unit tests
- [ ] no full Verovio render at playback-frame frequency
- [ ] no full React-tree update at playback-frame frequency
- [ ] measurements and known limits are documented

## Decision gate

This must pass before building the polished review workspace. Failure requires revisiting transport/renderer architecture before more UI polish.
