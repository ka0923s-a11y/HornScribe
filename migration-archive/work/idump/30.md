#30 UI-070: Accessibility, visual regression, usability, and performance quality gate

## Goal

Turn the GUI quality targets into repeatable release gates rather than subjective polish.

## Depends on

- all implemented UI surfaces

## Source of truth

docs/UX_VALIDATION.md

## Mandatory accessibility

- keyboard-only
- focus-visible
- Japanese accessible names
- semantic roles/states
- contrast
- color independence
- Narrator smoke
- 200% scaling smoke

## Mandatory visual matrix

- 1366x768 @100%
- 1920x1080 @100%
- 1920x1080 @150%
- 4K @150%
- light
- dark
- major errors
- review
- export

## Usability dogfood tasks

Record time/actions/friction for:

- open + transcribe
- create loop
- source-check a note
- correct + undo
- Concert/F-Horn switch
- process review item
- export F-Horn
- recover from missing MuseScore

## Performance

Record:

- cold shell interactive
- score render
- view switch
- note select
- seek latency
- playback-highlight latency
- waveform FPS/memory

## Acceptance criteria

- [ ] canonical Japanese golden screenshots exist
- [ ] axe/component checks pass where applicable
- [ ] keyboard-only primary flow passes
- [ ] Narrator major-flow smoke passes
- [ ] no repeated dogfood friction remains untracked
- [ ] performance measurements are recorded
- [ ] all error-recovery fixtures have non-dead-end actions
