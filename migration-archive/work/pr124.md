## 概要

GUI_UX_SPEC §13 の残り3つの音符編集（音価変更・発音位置グリッド移動・タイ切替）を実装します。これで §13 の編集機能が揃います。

## 変更内容

### エンジン (python)
- `transcription/scoreedit.py`（新規）: `score.edit` のドメイン実装
  - `setDuration` — 音符の記譜上の長さを変更
  - `shiftOnset` — 最小グリッド（`min_note_value_ql`）単位で発音位置を移動
  - `toggleTie` — 連続する同音高の次音符とのタイを切り替え
  - 編集対象を含む最小の小節揃えウィンドウを、量子化時と同じ `SpanRealizer` で再分解。休符ギャップ・連符グループ・メーター変更にも対応
  - 「次の発音を跨ぐ」「タイ相手がいない」「拍0より前」など正直に記譜できない編集は `ScoreEditError` で拒否（黙ってクリップしない）
- `worker/worker.py`: `"score.edit"` メソッドを登録。再構築した scoreDocument + 両 MusicXML + 新 scoreRevision（内容由来）を返す

### デスクトップ (apps/desktop)
- `score/rhythmEdits.ts`（新規）: `RhythmEditOp` / `ScoreEditResult` / n/d 分数パース・×2÷2 スケール・canonical ノート検索
- `score/document.ts` + `xmlDocument.ts`: `canonicalDocument()` / `contentSnapshot()` / `replaceContent()` を追加。エンジン編集はドキュメント内容をその場で差し替え（リマウントすると選択と undo スタックを失うため）
- `score/reviewSession.ts`: `docSwap` undo エントリ種別を追加 — リズム編集が既存の Ctrl+Z スタックに乗る
- `sidecar/session.ts`: `applyScoreEdit()` — ライブエンジンの `score.edit` を呼ぶ
- `score/ScoreReadyWorkspace.tsx`: `applyRhythmEdit`（promise キューで直列化 — 高速キー連打でも常に最新コンテンツに対して編集）+ `noteDurationScale` / `shiftSelectedOnset` / `toggleSelectedTie`
- `components/ScoreWorkspace.tsx`: ドキュメントインスタンス安定キー（WeakMap）— revisionId 変更ではリマウントしない
- `commands/definitions.ts` + `types.ts` + `ja.ts`: 5コマンド追加
  - `Ctrl+Shift+↑/↓` 音価を2倍/半分
  - `Ctrl+Shift+←/→` 発音位置を±1グリッド移動
  - `T` タイ切替
  - いずれも音符選択中かつ要確認ワークスペース外で有効
- `components/CommandBar.tsx`: overflow メニューにリズム編集項目（発見可能性のため）
- `App.tsx`: `applyRhythmEdit` invoker を `ScoreWorkspace` へ配線
