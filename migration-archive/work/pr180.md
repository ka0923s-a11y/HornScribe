## Summary

Fixes the biggest remaining accuracy gap in the pYIN backend: pyin is a continuous-f0 tracker with no onset notion, so re-articulated same-pitch notes (tongued repeats, repeated lyrics — everywhere in JPOP melodies) glued into a single long note. Closes #180.

## Changes

- HPSS preprocessing: `librosa.effects.harmonic` strips the percussive component before both pyin and onset detection, so JPOP mixes no longer let the band mask vocal attacks.
- Onset-driven splitting: `librosa.onset.onset_detect` (conservative delta=0.4 / wait=3 / backtrack) on the harmonic component produces attack times that are injected into `frames_to_note_events` via a new `onset_sec` parameter.
- Two guards keep splits honest: a split is skipped when either side would be shorter than min_note_sec, and when the voiced probability around the split frame stays above 85% of the run maximum (a solidly voiced frame means the tracker heard no break — the onset was a consonant or accent).
- `clean_monophonic` no longer re-merges same-pitch neighbours for pyin jobs (`merge_gap_sec=0`): the converter already bridges tracker dropouts, so the merge would silently undo onset splits.

## Verification

- New tests cover: onset inside a run with a prob dip splits into two notes sharing the split boundary; no dip keeps one note (accent guard); onset too close to an edge keeps one note (margin guard); onset outside the run is ignored.
- pytest tests/python, ruff, mypy all clean.
- librosa is an engine extra absent from the dev venv, so the pyin path is exercised through the pure converter; end-to-end smoke needs an [engine] install.
