## 問題

workflow_dispatch で tag に `0.1.0` (v 無し) を入力すると、checkout が
`refs/tags/0.1.0` を fetch しようとして失敗する (run 35993338213,
35993543130)。実際のタグは `v0.1.0`。

さらに publish ステップの `gh release view "$TAG"` も同じ値を使うため、
checkout を通過してもリリース名解決で同様に失敗する。

## 対応案

- 先頭にタグ正規化ステップを追加し、`v` プレフィックスの有無を吸収する
  (0.1.0 → v0.1.0、v0.1.0 → そのまま)。
- checkout 前に `gh api .../git/ref/tags/<tag>` でタグの存在を検証し、
  存在しない場合は分かりやすいエラーで即失敗させる。
- 以降のステップは正規化済みタグを参照する。
