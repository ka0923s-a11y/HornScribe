## 概要
ブラウザ dev 環境 (`vite dev`) で `kind:"file"` ドロップやパスなし録音が実エンジンに届かず、常にモックエンジンしか動かなかった問題を解消します (#86)。

## 変更点
- `scripts/devEngineBridge.mjs`: Vite ミドルウェア。同一オリジンの localhost HTTP+SSE でワーカーライフサイクルを公開:
  - `GET /__engine/health`, `POST /spawn`, `POST /write`, `POST /stdin-close`, `POST /kill`, `GET /events` (SSE: line/stderr/exit)
  - `POST /stage`: ブラウザ保持バイトを `%TEMP%/hornscribe-dev/` に書き出し `{path}` を返す
  - Python 解決は engine.rs と同順序 (HORNSCRIBE_PYTHON → リポジトリ内 .venv* → PATH)、PYTHONPATH は `<repo>/python`
- `src/sidecar/devBridgePort.ts`: `TauriSidecarPort` と同形状の SidecarPort。`/health` をプローブし、ブリッジが無ければ `MockSidecarPort` に委譲 (従来どおりの dev 体験を維持)
- `src/import/staging.ts`: `kind:"file"` / パスなし録音 blob を `/stage` に POST。`buildTranscriptionParams` に `stagedAudioPath` 第3引数を追加し、staged パスが最優先
- `engine.rs` + ブリッジの venv 解決を修正: 名前ヒューリスティック (`bp` 含有/名前長) ではなく、ワーカーが実際に動く環境 (music21 = 必須 import, basic_pitch = 機能) でランク付け。古い basic-pitch-only 環境は music21 不在で worker が import 時にクラッシュしていた

## 検証

- `/stage` で WAV 書き出し → 実パス返却を確認
- vitest 347 件 / tsc / eslint すべてグリーン
