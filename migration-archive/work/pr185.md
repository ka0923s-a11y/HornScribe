## Summary

ScoreDocument.transcriptionBackend / transcriptionBackendVersion were hardcoded to basic_pitch/0.4.0 in build_score, so pYIN jobs mis-recorded their provenance in the project file. Closes #185.

## Changes

- build_score accepts transcription_backend / transcription_backend_version kwargs.
- The pipeline resolves backend_id + backend_version once and feeds both the ScoreDocument and the job meta, so the two provenance surfaces can no longer disagree.

## Verification

- New test asserts a pyin job records transcriptionBackend=pyin on the scoreDocument and meta.backend=pyin.
- pytest / ruff clean.
